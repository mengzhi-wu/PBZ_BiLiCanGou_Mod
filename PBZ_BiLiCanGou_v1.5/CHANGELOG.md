# 更新记录

## v1.5 正式版（2026-11-19）

**最终规则（本版定稿）**

| 情况 | 返还 | 时机 |
|---|---|---|
| 普通攻击反制成功 | 35%（每周期一次） | 反制成功那一帧 |
| 黑光 / 蓝光反制成功 | 杀气恢复满 100% | 判定帧消失那一帧（不依赖架势标签，周期外也生效） |
| 整周期无成功反制 | 50% | 架势动作结束当帧先返，延迟消耗再补差 |

- 瞬时反制：判定帧一出现就按「格挡 + 重击」（`trigger_frames = 0`，可改 2 试手感）。
- 热键：F1 杀气返还开关、F2 瞬时反制开关（按键屏幕提示）、F7 状态写日志、F9 紧急停止。
- 安装包：`install.bat` / `check.bat` / `uninstall.bat`，支持玩家自填游戏根目录；版本显示走 `VERSION.txt`。
- 单测 81 项全通过。

## v1.4.3（2026-11-19）

- 瞬时反制改回 **0 帧触发**：判定帧一出现就按「格挡 + 重击」，不再等待第二帧。
  `instant_counter.trigger_frames` 默认 0（0 / 1 都表示出现即打，2 表示等第 2 帧）。

## v1.4.2（2026-11-19）

**瞬时反制改为 2 帧触发**

- 新增 `instant_counter.trigger_frames = 2`：同一条判定帧要连续出现 2 帧（2 次采样，约 0.1 秒）才按键，
  避开「帧刚出现就按、时机太早 → 空放」；改成 1 即回到第一帧就出手的老行为。
- 换了判定帧（handle 变化）会重新计数，不会拿上一招的帧数凑数。

**安装 / 卸载驱动更新**

- 安装包内新增 `VERSION.txt`，安装、卸载、体检都会显示实际安装版本。
- 安装时会自动修复历史遗留的 `.bak-` 备份：把备份里的 `enabled.txt` 改名，避免被 PBZModsMenuBridge 索引成第二个 mod。
- 卸载同样会修一遍遗留备份；新增 `uninstall.bat -PurgeBackups` 可连备份一起删除（默认保留，会二次确认）。
- 安装完成提示的热键更新为 F1 / F2 / F7 / F9。
- 单测增至 82 项。

## v1.4.1（2026-11-19）

**测试版：修「黑光/蓝光杀气回满不触发」**

- 根因：旧逻辑只在架势标签在身时扫判定帧，而标签常常 0.5 秒就灭，黑/蓝光反制多发生在标签灭后 —— 整场 36 个周期只认到 1 次普通反制，黑蓝 0 次（回满代码从未被调用）。
- 改为**全程监听 `DeflectComponent.ReceiveFrames`**：黑/蓝光判定帧消失即判反制成功，立即回满杀气；架势已收、甚至周期已结算，也照样回满。
- `IsDodge=true` 的帧（闪避掉）不算反制。
- 采样间隔 100ms → 50ms，减少短窗口漏采。
- 日志新增 `判定帧出现 #handle 类型 ...`，便于核对帧类型是否解析正确。
- 单测 79 项全通过。

## v1.4（2026-11-19）

**规则调整：黑光 / 蓝光改成「恢复满杀气」**

- 反制黑光 / 蓝光成功的那一刻，直接把杀气（`BasicAttributeSet.Shachi`）恢复到上限 100%，
  不再按「本次消耗的百分比」计算；判定成功即触发。
- 普通攻击反制仍是当场返 35%；整周期无成功反制仍是结束后返 50%。
- 旧的比例口径保留为可选项：`refund.black_blue_fill_max = false` 时回到「补足到本次消耗 100%」，
  并在周期结算时补齐后续新增消耗。
- 单测增至 73 项（黑光/蓝光改为断言 `fill_max` 事件，比例模式另测）。

**返还时机（并入 v1.4.1）**

- 「整个周期没有成功反制」的 50%，改为**架势动作结束的那一刻立即返还**（按当时已扣的消耗算一半），
  不再等 4 秒观察窗结束才出现。
- 真实游戏里有 1~3 秒的延迟扣除，所以结束当帧先返一笔，尾部观察窗里再按最终消耗补差到 50%；
  日志会看到 `unsuccessful_partial`（架势结束先返）与 `unsuccessful_topup`（补差）两笔。
- 单测增至 77 项。

**黑/蓝光不触发的修复（v1.4.1）**

- 根因：判定帧只在「架势标签在身」时才被扫描，而真实战斗里标签经常 0.5 秒就灭，
  黑/蓝光的反制多半发生在标签灭掉之后，导致整场 36 个架势周期只认到 1 次普通反制、黑蓝 0 次。
- 改为**全程监听 `DeflectComponent.ReceiveFrames`**（不再依赖架势状态）：
  黑/蓝光判定帧消失 = 反制成功 → 立即把杀气恢复到 100%，即使当前周期已经结算也照样回满。
- 闪避掉的帧（`IsDodge=true`）不算反制。
- 采样间隔 100ms → 50ms，减少短判定窗口漏采。
- 日志新增判定帧出现记录（`判定帧出现 #handle 类型 PowerAttack/Normal/...`），便于下次核对。
- 单测增至 79 项。

## v1.2（2026-11-18）

**修复：杀气返还几乎不生效（基数 0.00~18.96，返还 0~9 点）**

从玩家日志定位到根因：架势标签只亮 0.5 秒，而真正的消耗在标签消失后 1~3 秒才扣
（806.8 起手 → 标签熄灭 → 数秒后掉到 570.7）。旧逻辑一灭就算账，所以永远只量到零头。

- 新增**尾部观察窗** `refund.tail_seconds`（默认 4.0）：标签消失后继续累计这段时间内的煞气下降，
  到期才结算。实测场景下 236 的消耗会正确进入基数，按 50% 返 118。
- 窗口内若又起了新架势，先结算上一周期再开新周期，不串账。
- 起手补记上限 `seed_cap` 由 200 放宽到 500（原来 236 的起手消耗会被判成「异常」直接丢弃）。

**新增：F7 设置菜单**

- F7 打开/关闭屏幕左上角的设置菜单，实时显示：杀气返还开关、瞬时反制开关、紧急停止状态、
  当前煞气、本周期消耗与已返数值、当前规则。
- 菜单内直接按键：F8 开关杀气返还、F6 开关瞬时反制、F9 紧急停止，状态立刻刷新。
- 菜单用引擎自带 `PrintString` 画屏幕文字，不依赖额外 UI 资源；若构建不支持，会自动改为每 3 秒把同一份内容写日志。
- 新增控制台 `pbzkg menu on/off`。

**其它**

- 修复 `pbzkg reload` 读不到 `config.lua` 的问题（之前用的是被局部覆盖的 `load`，路径也不对）。

## v1.1（2026-11-18）

依据玩家上传的真实 `UE4SS.log` 修正「能加载但关键信号读不到」的问题。

**修复**

- 判定帧组件改为三级查找：角色属性 `DeflectComponent` → `FindAllOf('DeflectComponent')` 用 Outer/Owner 地址对齐玩家 → 单人唯一实例。
  日志里的 `DeflectComponent: 未找到` 由此解决。
- 武器识别增加兜底：背包子系统取不到时，扫挂在玩家身上的 `BP_Weapon_*DualHook*` 武器 Actor。
  读取方式原来只认背包字段，导致日志里 `当前武器: nil`。
- 重击动作名缺失时，扫描全部 `InputAction` 按关键词匹配（`AttackH` / `AttackHeavy` / `HeavyAttack` / `StrongAttack`），
  不再因为 `IA_AttackH_*` 不在候选表里就直接停用瞬时反制。
- 架势起手那一口消耗改为「上一帧煞气 − 本帧」补记，修复多个周期 `基数 0.00` 的问题；
  补记有上限 `refund.seed_cap`（默认 200），复活/换人不会被算成巨额消耗。

**新增**

- `pbzkg probe`：一次性 dump 判定帧组件实例（含 Outer 地址、判定帧数量）、InputAction 全量名单里的相关项、
  DualHook 武器 Actor 及其挂点、背包 `MainWeapons` / `CurrentWeaponIndex`，用于定位缺失符号。
- 安装脚本备份旧版时把备份目录里的 `enabled.txt` 改名为 `enabled.txt.bak`，
  避免 `PBZModsMenuBridge` 把 `.bak-时间戳` 目录也索引成一个 mod。
- 单测增至 63 项（新增起手补记、补记上限两组）。

## v1.0（2026-11-18）

首个版本。

**功能**

- 瞬时反制：检测到可反制的来袭攻击（普通 / 黑光 / 蓝光）时，自动「按住格挡 + 按重击」在第一帧起架。
  - 杀气门槛默认 37%，可调；未持别离残钩（`DualHook`）时不动手。
  - 有冷却，避免连续起架。
- 杀气返还：
  - 成功反制普通攻击 → 本次架势消耗的 15%，每周期一次；
  - 成功反制黑光/蓝光 → 补足到本次架势消耗的 100%；
  - 未成功反制（失败或空放）→ 20%（取代早期设想的 30%）；
  - 每周期累计上限 100%，无额外惩罚。
- 架势周期由 GameplayTag `Ability.Action.Stance` 驱动；消耗按 `BasicAttributeSet.Shachi` 逐帧累计，
  忽略自身返还造成的上升。
- 诊断面板（F7）+ dry-run + 连续写失败自动停写 + 紧急停止。
- 58 项脱机单测（`tests/run_tests.lua`）。

**安装工具**

- `install.bat`：由玩家指定游戏根目录（拖拽 / 粘贴 / 弹窗选择三种方式），自动定位 `PBZ.exe` 与 `ue4ss`，
  校验 UE4SS，复制文件，备份旧版本，生成 `enabled.txt`，修正 `mods.txt`（改动前自动备份），
  并记住本次目录供下次复用。
- `check.bat`：逐项体检（游戏目录 / UE4SS / mod 目录 / 脚本数量 / `enabled.txt` / `mods.txt` 状态 / 日志尾部），
  无参数时直接沿用上次的目录。
- `uninstall.bat`：删除 mod 目录并清理 `mods.txt` 记录，不动游戏本体与存档。
- 三个 bat 调用的实现都在 `tools\PBZModSetup.ps1`，路径按位置传参（`install.bat "D:\...\PBZ"`），
  另支持 `-Force`。

**已知边界**

- 「成功反制」默认用判定帧消失推断，可切换为动画信号；
- 「瞬时反制」通过注入按键实现，不是修改动画判定窗口本身。
